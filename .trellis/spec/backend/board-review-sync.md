# Board Review Sync Contract

> Scope: Cloud backend device configuration, review-result sync API, STM32MP157 board writeback client, reverse-tunnel deployment, and verification.

---

## Scenario: Cloud Review Corrects Board-Side Detection Result

### 1. Scope / Trigger

- Trigger: The operator opens a detection record and clicks `修正板端结果`.
- Trigger: The cloud final result is authoritative and must update the STM32MP157 local history row.
- Trigger: The board uploads detection records to the public cloud but the public cloud cannot directly reach the board LAN/PPP private address.
- Backend route: `POST /api/v1/records/{record_id}/sync-board-review`.
- Device fields: `board_review_url`, `board_review_token`, `has_board_review_token`.
- Board endpoint contract: `POST /api/v1/review-result`.
- Production cloud host used in validation: `119.91.65.122`.
- Production reverse tunnel endpoint used in validation: `http://127.0.0.1:18081/api/v1/review-result`.

### 2. Signatures

| Operation | Signature |
|---|---|
| Device create/update schema | `DeviceCreateRequest.board_review_url`, `DeviceCreateRequest.board_review_token`, `DeviceUpdateRequest.board_review_url`, `DeviceUpdateRequest.board_review_token` |
| Device response schema | `DeviceResponse.board_review_url`, `DeviceResponse.has_board_review_token` |
| Device ORM fields | `Device.board_review_url: String(255)`, `Device.board_review_token: String(255)` |
| Sync request schema | `BoardReviewSyncRequest(decision, cloud_reason, defect_type=None, reviewed_at=None)` |
| Sync response schema | `BoardReviewSyncResponse(review, board_sync_status, board_sync_time, board_sync_error)` |
| Sync API | `POST /api/v1/records/{record_id}/sync-board-review` |
| Board client call | `httpx.post(url, json=payload, headers={"X-Board-Token": token}, timeout=5.0)` |
| Board payload builder | `ReviewService._build_board_payload(record, review, reviewer_name) -> dict[str, Any]` |
| URL validator | `ReviewService._validate_board_review_url(url)` allows only `http` and `https` with a non-empty host |

### 3. Contracts

#### Cloud Device Configuration

| Field | Required For Sync | Meaning |
|---|---|---|
| `board_review_url` | yes | Full URL that the cloud backend process can reach. It is not a browser-only address. |
| `board_review_token` | yes | Secret sent as `X-Board-Token`; the response must expose only `has_board_review_token`, not the token value. |
| `has_board_review_token` | response only | Boolean display flag for frontend device management. |

#### Cloud Sync Request

| Field | Type | Required | Meaning |
|---|---|---|---|
| `decision` | enum | yes | Cloud final decision. Allowed values follow `DetectionResult`: `good`, `bad`, `uncertain`. |
| `cloud_reason` | string | yes | Operator reason from the correction dialog. Must be non-empty and sent to the board. |
| `defect_type` | string or null | no | Optional cloud-side defect type for the review record. |
| `reviewed_at` | datetime or null | no | Optional review timestamp; backend fills current time when omitted. |

#### Board Payload Generated By Cloud

| Field | Source | Board Meaning |
|---|---|---|
| `record_id` | `str(record.id)` | Board local row lookup key. |
| `record_no` | `record.record_no` | Board local row lookup fallback/display key. |
| `cloud_result` | `map_cloud_result_to_board(review.decision)` | `good`, `bad`, or `review`; `uncertain` maps to `review`. |
| `cloud_reason` | `review.comment` | Correction reason. |
| `operator` | current user display name or username | Cloud reviewer. |
| `review_time` | `review.reviewed_at.astimezone().strftime("%Y-%m-%d %H:%M:%S")` | Board display time. |
| `source` | literal `cloud` | Origin marker. |

#### Sync Persistence

| Step | Contract |
|---|---|
| Review creation | Create a manual `ReviewRecord` before calling the board. The cloud review is retained even if board sync fails. |
| Record status | Set `DetectionRecord.review_status=reviewed` once the cloud review is created. |
| Missing device URL | Mark `board_sync_status=failed` with `board_sync_error="当前设备未配置板端回写地址。"` |
| Missing token | Mark `board_sync_status=failed` with `board_sync_error="当前设备未配置板端回写密钥。"` |
| Board success | Set `board_sync_status=success`, `board_sync_time=<now>`, `board_sync_error=null`, and `board_last_synced_review_id=<review.id>`. |
| Board failure | Set `board_sync_status=failed` and preserve the board/client error text in `board_sync_error`. |

#### Reachability Rule

`board_review_url` must be reachable from the cloud backend process, not from:

- the operator's browser,
- the developer's Windows machine,
- the VM on the same LAN as the board.

When the board is behind LAN NAT or 4G carrier NAT, use a reverse tunnel:

```text
cloud backend -> http://127.0.0.1:18081/api/v1/review-result
              -> SSH reverse tunnel
              -> board http://127.0.0.1:18080/api/v1/review-result
```

### 4. Validation & Error Matrix

| Condition | Cloud Behavior | Expected Error / Status |
|---|---|---|
| Record id not found in company | Raise `record_not_found` | API returns not found error |
| `cloud_reason` blank | Reject before review sync | `board_review_reason_required` |
| `board_review_url` empty | Keep review, mark sync failed | `当前设备未配置板端回写地址。` |
| `board_review_token` empty | Keep review, mark sync failed | `当前设备未配置板端回写密钥。` |
| URL missing scheme or host | Reject URL before HTTP call | `board_review_url_invalid` |
| Board HTTP timeout | Keep review, mark sync failed | `连接板端超时，请检查开发板网络和回写地址。` |
| Board network error | Keep review, mark sync failed | `连接板端失败：<error>` |
| Board returns `401` | Keep review, mark sync failed | `板端密钥错误。` |
| Board returns `404` | Keep review, mark sync failed | `板端找不到对应检测记录，检查 record_id/record_no。` |
| Board returns `4xx/5xx` | Keep review, mark sync failed | `板端返回 HTTP <status>：<body>` |
| Board returns invalid JSON | Keep review, mark sync failed | `板端返回内容不是有效 JSON。` |
| Board JSON `ok` is not true | Keep review, mark sync failed | Board `error` or `message` |
| Board JSON `ok=true` | Mark sync success | `board_sync_status=success` |

### 5. Good/Base/Bad Cases

| Case | Example | Expected Result |
|---|---|---|
| Good reverse-tunnel URL | `board_review_url=http://127.0.0.1:18081/api/v1/review-result` on the production cloud server | Cloud backend reaches the board while the board remains behind NAT |
| Good real sync | Record `91 / MP157-20260519-211550` corrected to `bad` | Response `board_sync_status=success`; board local history shows the cloud reason |
| Good fake-record smoke test | Cloud server posts through `127.0.0.1:18081` with fake `record_id` and correct token | Board returns `404 记录不存在`, proving routing and token are correct |
| Base normal LAN-only test | Developer browser can curl `192.168.1.250:18080` | Useful only for local board endpoint validation, not cloud reachability |
| Bad private IP config | `board_review_url=http://192.168.1.250:18080/api/v1/review-result` on public cloud | Cloud backend cannot reach the LAN address |
| Bad PPP IP config | `board_review_url=http://10.x.x.x:18080/api/v1/review-result` | Cloud backend cannot reach private/carrier-NAT PPP address |
| Bad token display | API response includes `board_review_token` plaintext | Secret leakage; return only `has_board_review_token` |
| Bad all-or-nothing sync | If board call fails, rollback the cloud review | Operator decision is lost; cloud review must persist and sync status must show failure |

### 6. Tests Required

- Unit/service tests:
  - Assert `map_cloud_result_to_board(DetectionResult.UNCERTAIN) == "review"`.
  - Assert blank `cloud_reason` raises `board_review_reason_required`.
  - Assert missing URL creates review and returns `board_sync_status=failed`.
  - Assert missing token creates review and returns `board_sync_status=failed`.
  - Assert board client `401`, `404`, timeout, invalid JSON, and `ok=false` map to stable user-facing errors.
  - Assert board success sets `board_sync_status=success`, `board_sync_error=None`, and `board_last_synced_review_id`.
- API tests:
  - Assert `POST /api/v1/records/{id}/sync-board-review` returns `BoardReviewSyncResponse`.
  - Assert the final mounted route is under `/api/v1/records/...`, not `/api/v1/reviews/records/...`.
  - Assert device response does not return plaintext `board_review_token`.
- Production verification:
  - On the cloud server, assert `ss -lntp | grep 18081` shows `127.0.0.1:18081`.
  - From the cloud server, token POST to `http://127.0.0.1:18081/api/v1/review-result` with a fake record should return board JSON `404 记录不存在`.
  - For a real record existing in board history, assert sync returns `success`, cloud DB record status is `success`, and board `upload_history.json` contains the corrected result and reason.

### 7. Wrong vs Correct

#### Wrong

```text
board_review_url = http://192.168.1.250:18080/api/v1/review-result
```

This address can be reached only from the board LAN or VM. A public production backend cannot call it.

#### Correct

```text
board_review_url = http://127.0.0.1:18081/api/v1/review-result
```

This address is correct only when the board has established the reverse SSH tunnel to the production cloud server.

#### Wrong

```python
# Wrong: losing the cloud decision when board sync fails.
review = create_review(...)
ok = board_client.post_review(...)
if not ok:
    db.rollback()
```

#### Correct

```python
# Correct: cloud review is durable; board sync is a status field on the detection record.
review = create_review(...)
db.commit()
ok, error = board_client.post_review(...)
if ok:
    record.board_sync_status = "success"
    record.board_last_synced_review_id = review.id
else:
    record.board_sync_status = "failed"
    record.board_sync_error = error
db.commit()
```

#### Wrong

```typescript
// Wrong: expose a secret back to the frontend.
type DeviceDto = {
  board_review_token: string;
};
```

#### Correct

```typescript
// Correct: frontend can show configured/unconfigured state without seeing the token.
type DeviceDto = {
  board_review_url: string | null;
  has_board_review_token: boolean;
};
```
